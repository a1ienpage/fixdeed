# Fixdeed hackathon MVP
User-authorized scope: fix the audited safety, savings, recurrence and learning problems, redesign the complete English B2C web application for US adults 25–45, then verify it. Existing Next.js implementation retained. Work occurs in an isolated copy because original is not a Git repository; no cloud deployment or paid model calls are required. Original environment files remain untouched.

## Experience
An editorial home page explains value before any diagnostic case. Dark ink, warm off-white, violet and restrained acid-lime inspired by Zimran. Large typography, thin borders, purposeful motion, custom code-native house/technical illustrations, no emoji, no old generated photography. Separate tools: guided triage, recurring maintenance, home ledger, skill practice, contextual assistant. Responsive, keyboard accessible, respects reduced motion.

## Product rules
Unknown symptoms never produce a guessed repair. Emergency checks apply before/after model output and persist through assistant follow-ups. Conflicting clarifying answers override generic guides. Rule fallback never claims image analysis. Model content must not bypass curated safety. No verified/safe/health guarantees.
Fresh personal state contains no fabricated repairs or savings. Demo mode is explicit and separate. Learning awards skills only after a new transfer scenario; never money or repair completion. Savings are user-reported quote minus actual costs on explicitly confirmed repairs, separate from illustrative estimates. Duplicated form submissions are idempotent. Calendar tasks recur by cadence with due/overdue/upcoming dates. Readiness is task coverage, not an inspection or physical health score. Personal data is browser-local with export and delete controls, no background image persistence. Pricing described as planned, not a functional payment subscription.

## Approaches
A cosmetic reskin would preserve incorrect product behavior. A replacement stack would add migration cost. Selected builder approach: keep Next.js and existing route structure, replace the presentation layer and repair the underlying domain behavior. User requested implementation and delegated visual choices; these are builder decisions within that request.

## Verification
Regression tests for ordinary emergency wording, unknown text, image fallback, hazardous model output, assistant emergency history; money/date/idempotence/recurrence/skill tests; TypeScript; offline-capable production build; real browser desktop/mobile journeys.
